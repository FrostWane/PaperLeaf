# PaperLeaf 测试指南

## 质量目标

测试按“确定性业务、检索质量、Agent 控制、用户界面、部署安全”分层。任何准确率或性能改进必须由相同数据、相同协议和可定位的提交支持。

## 本地快速检查

前端：

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm storybook:build
pnpm exec playwright install chromium
pnpm test:e2e
```

后端：

```bash
cd backend
python -m pip install -e ".[dev]"
python -m compileall paperleaf_api tests
ruff check paperleaf_api tests
pytest
```

容器：

```bash
docker compose --env-file .env.example config --quiet
docker compose --env-file .env.example build web api worker
# 服务启动后，从环境变量读取管理员凭证并执行临时数据闭环
python scripts/smoke_compose.py
```

GitHub Actions 对拉取请求执行上述检查并运行密钥扫描。后端任务会启动独立 pgvector PostgreSQL，依次验证全新 `upgrade head`、回退到 0.2.0 结构、再次升级和 `alembic check`，避免只在内存仓储上通过。

当前仓库的可执行基线为：后端 Pytest 22 项、前端 Vitest 13 项；Playwright 定义 8 个场景，并在 2560、1440、768、390 四个 Chromium 视口项目中运行。Compose 冒烟脚本除上传、解析、Range、管理员端点和删除外，还会验证最近阅读、集合/标签归属与批量归档；真实 PostgreSQL 迁移由 CI 的独立数据库门禁重复验证。数字来自最近一次发布审计的实际命令输出，后续应以 CI 当次报告为准。

## 当前后端自动化范围

- 生产占位密钥与过短密钥拒绝。
- 登录、首次修改密码门禁、CSRF、停用用户会话撤销与跨用户文献隔离。
- 集合/标签归属返回、最近阅读、批量整理/归档、跨用户批量操作隔离、管理员任务列表与失败任务重试。
- PDF 文件头、单段与后缀 Range、本地对象幂等删除。
- 论文删除作业只入队一次。
- 页内切块参数、RRF、引用页/片段校验与非法引用拒绝。
- Agent 有证据回答、无证据拒答、伪造引用抑制、arXiv 导入前中断、用户/运行级线程隔离和应用重建后恢复。
- 评测器原始分子/分母、不可回答错误率与非法引用计数。

当前 Pytest 主要使用内存仓储和本地临时对象存储；上述 Compose 冒烟补充验证了 PostgreSQL/pgvector、MinIO、真实迁移和 Worker 领取任务，但尚未接入 CI/Testcontainers，也没有覆盖并发与故障注入。后续自动化容器测试必须使用临时数据库与独立 Bucket，不能连接开发者的真实数据。

## RAG 评测

以下是发布评测目标，不是当前成绩。计划冻结至少 20 篇可合法分发的开放文献和 120 个问题，覆盖：

- 单页事实
- 跨页综合
- 方法与实验结果
- 具有相似术语的干扰文献
- 文库中不可回答的问题
- 文献内提示词注入与伪工具指令

主要指标：

| 指标 | 目标 |
|---|---:|
| Recall@5 | ≥ 85% |
| 关键事实正确率 | ≥ 80% |
| 引用物理页准确率 | ≥ 95% |
| 有依据事实的引用覆盖率 | ≥ 90% |
| 不可回答问题错误作答率 | ≤ 5% |
| 非法引用 | 0 |

每次实验保存数据集版本、基线与候选提交、模型、提示词、随机设置、原始计数、绝对变化、相对变化、失败样本和运行时间。协议或数据不同的结果不得直接比较。

仓库目前提供 `backend/evaluation` JSONL 协议、Schema 和指标计算器，不附带评测语料、预测文件或分数，因此不能宣称已经达到上表目标。

## Agent 测试

- 当前自动化验证有证据回答、无证据拒答、伪造引用被服务端抑制，以及联网检索在导入前中断。
- 图为有限无环路由，调用处的 `recursion_limit` 为 8；当前没有“最多四步”的独立限流器。
- SSE 解析器通过前端单元测试验证分片、多个事件和错误帧。
- PostgreSQL Checkpoint 的真实容器重启、重复 Resume、取消竞态、工具超时及真实 arXiv 故障仍属于发布前补充场景。

工具调用成功率 ≥95%、中断恢复成功率 100%、跨用户泄露为 0 均为发布目标；在对应容器测试和故障注入完成前不发布这些指标。

## 前端与无障碍

当前 Vitest 覆盖登录表单校验、登录/改密/上传/单篇文献/聊天 API 契约、文献修改/重试/删除、总结与结构图映射、集合/标签 CRUD、批量动作与最近阅读，以及 SSE 分片、连续事件和错误事件。Storybook 提供上传弹窗、论文工作台、文献组织工作台和组织管理弹层供人工检查。

当前 Playwright 自动化场景为：

1. 公开演示提问后从引用跳转到对应论文页。
2. 首页 WCAG 2 A/AA axe 扫描无违规。
3. 论文工作台 axe `serious`/`critical` 为 0。
4. 生成证据化概览，点击证据跳转到对应物理页，并构建结构图。
5. 编辑文献元数据，验证删除必须经过二次确认。
6. 2560×1440 下验证关键阅读字号与横向溢出。
7. 创建、修改和删除组织项，批量加入与移出集合，并验证真实筛选数量。
8. 批量归档和恢复，四视口检查页面与表格均无非预期横向溢出，并执行文献组织 axe 扫描。

它们分别在 2560×1440、1440×900 桌面、768×1024 平板和 390×844 Pixel 7 移动 Chromium 项目中运行。字号专项仅在 2K 项目执行；0.2.1 的完整结果应为 29 项通过、3 项按设计跳过，以当次 CI 报告为准。失败时保留 Trace 和截图；仓库尚未启用基于基准图的像素差异门禁。

以下是后续端到端与人工发布验收清单，并非当前 Playwright 覆盖：

1. 登录与首次修改密码。
2. 上传 PDF，观察解析进度并打开阅读器。
3. 提问，接收流式回答并跳转到正确物理页。
4. 修改标签和集合；组织 CRUD、批量归属、归档、元数据编辑和二次确认删除已进入自动化覆盖。
5. 搜索 arXiv，拒绝一次导入，再确认一次导入。
6. 管理员创建和停用用户，验证内容不可跨用户读取。

发布前应补 Firefox、WebKit、真实 PDF 上传以及生产 API 模式，并结合语义断言、溢出检查和人工截图确认。

无障碍门禁：

- axe `serious` 与 `critical` 为 0。
- 核心路径可全键盘完成，焦点顺序与焦点环可见。
- 200% 缩放不丢失功能，不出现非预期横向滚动。
- 状态同时包含文字或图形，不只依赖淡蓝、淡绿或红色。
- 触摸目标至少 44 × 44 CSS 像素。

性能目标：LCP ≤ 2.5 秒、INP ≤ 200 毫秒、CLS ≤ 0.1，字体导致的 CLS ≤ 0.02。当前仓库尚未提交 Lighthouse 基线，不能把目标写成已达成结果；后续报告必须注明硬件、网络配置、数据规模和运行次数。
