# 有界并行跨文献比较开发报告

## 结论

PaperLeaf 已完成 `compare_papers` 的 Phase 1 改造：复杂的 3～10 篇跨文献任务可在同一个父
`AgentRun` 内拆成最多 3 个只读证据分支，并行召回后由服务端确定性合并，再交给原有回答、
引用合法性和语义支持链路处理。

当前能力应准确称为“有界并行 Map-Reduce RAG”，而不是多个可自由通信、各自拥有长期状态的
Agent Team。是否进入带独立推理上下文的 Phase 2，必须等待冻结数据集的真实 v1/v2 配对评测和
人工盲评结果。

## 改造前的结构问题

原链路只有一个 Agent Graph。Function Tool Harness 可以并行调用工具，但跨文献比较仍由一次
检索和一次回答完成，容易出现某一篇论文占满证据、部分论文没有被覆盖等问题。直接叠加
Supervisor 又会引入双重规划、并行状态覆盖、子 Run 唯一约束冲突和 Checkpoint 版本污染。

因此本轮没有创建子 `AgentRun`，也没有修改上传、解析、翻译、单篇问答和写操作审批链路。

## 实现方案

```text
服务端冻结用户、会话、论文范围与编排版本
→ Context Engine 与 Skill 路由
→ 最多 3 个只读 Evidence Scout 并行检索
→ 按 Chunk、论文和物理页复验、去重、轮转合并
→ 原有 LangGraph 回答生成
→ 引用合法性与语义支持门禁
→ 持久化消息、事件和聚合指标
```

核心约束：

- 仅集合或全库范围、3～10 篇论文、`compare_papers` Skill 才能进入 v2。
- 分支只获得冻结后的论文子集和本地只读检索器；没有联网、导入、删除、Memory 写入或审批权限。
- 最大并行数为 3，分支超时、总超时和父 Token 预算均可配置。
- Scout 返回的候选只以合法 Chunk ID 为依据；合并阶段再次检查父 scope、分支 scope、物理页和论文。
- 部分分支失败时保留成功结果并显示覆盖提示；全部失败、计划非法或超时时回退原 v1 检索。
- 父 Worker 取消或失租时取消并行任务；旧 Worker 的迟到事件和最终写入由 `claim_token` fencing 拒绝。
- Run 创建时冻结 `orchestration_version`，Feature Flag 关闭后新 Run 立即走 v1。

## 数据、事件与管理观测

数据库新增 `agent_runs.orchestration_version`，迁移版本为 `20260812_0019`。并行过程复用现有
`agent_run_events`，只公开 `s1`～`s3`、状态、耗时和数量，不公开问题、论文 ID、Chunk ID、
工具参数或模型内部计划。

聊天区新增紧凑的“并行跨文献比较”进度，展示计划、各组分析、合并和安全回退。管理员 Harness
页面新增聚合指标：运行数、子任务成功率、部分完成、回退、P50/P95、候选证据、去重和冲突数量。
指标不使用用户 ID、论文 ID 或问题作为标签。

## 评测框架

新增独立的 `multi-agent-compare-v1` 数据集与配对评测器，不修改旧 RAG 指标口径：

- 48 个样本：36 个复杂任务和 12 个单篇、不可回答、提示注入、越权对照。
- 复杂任务覆盖 3～10 篇论文，复用既有页级证据锚点。
- A/B 顺序按用例稳定散列为 AB 或 BA，并校验问题、scope、语料快照和模型配置一致。
- 同时记录预期主张证据覆盖、输出主张支持精度、论文/维度/冲突覆盖、引用、安全、耗时和估算 Token。
- 当前数据集仍是 `draft`，缺少人工盲评，因此评测结论固定为 `quality_pending`，不得声称 v2 优于 v1。
- Live 采集器会验证论文版本、Chunk 文本锚点、所有者、scope 和物理页；未知指标明确记为
  `not_measured`，不会用 0 冒充已测结果。

### 真实 DeepSeek + Ollama + PostgreSQL 闭环

第一次真实运行暴露了一个问题：“当前文献库中这些论文”被旧指代规则误判为缺少上下文。
修复为“显式集合/文献库范围 + 论文名词”可直接绑定服务端冻结 scope；裸句“这些讲了什么”仍会
要求澄清，避免猜错范围。

修复后保留了两条可在界面检查的真实会话：

| 场景 | Run | 结果 |
|---|---|---|
| 全库 10 篇系统比较 | `af46b91e-806e-49af-b931-3f8cc0a7d0a8` | v2；3/3 分支成功；18 条合并证据；2218 字；15/15 引用合法；覆盖 9 篇 |
| DTA 集合 5 篇方法与实验归纳 | `81b33f2a-096c-4c0b-b795-0df9b39c8fa7` | v2；3/3 分支成功；18 条合并证据；2409 字；14/14 引用合法；覆盖 5 篇 |

两条 Run 都只有一个父 `AgentRun`，没有创建子 Run。第一条约 135.5 秒，第二条约 154.5 秒。
引用均通过用户所有权、冻结论文范围、Chunk ID 和物理页校验。

本轮语义支持模型在真实运行中不可用，因此答案走“引用合法的保守降级”，不能把这两条结果写成
逐条语义支持已经通过。离线配对预检也因本地缺少冻结集所需的 2 篇论文而明确返回
`not_executed / quality_pending`，没有缩小 scope 或伪造质量分数。

## 如何本地验收

1. 打开 `http://localhost:3000/ask`，选择包含 3～10 篇 Ready 文献的集合。
2. 新建会话，输入：`总结这五篇论文的方法和实验，并说明各自最值得注意的差异。`
3. 运行中应看到“并行跨文献比较”，其下最多出现 3 个分析组和一个合并阶段。
4. 页面可以离开后再返回；父 Run 继续在 Worker 中执行。
5. 完成后检查回答中的引用可跳到正确论文和物理页。
6. 管理员进入“管理 → Harness”，在“跨文献并行比较”查看运行、分支成功率、回退和耗时。
7. 将 `PAPERLEAF_MULTI_AGENT_ENABLED=false` 后重建 API/Worker，新 Run 应恢复
   `single_agent_v1`；已有 Run 保留创建时冻结的版本。

## 局限与下一步

- Phase 1 的 Coordinator 是确定性计划器，Scout 是隔离的并行只读检索任务，不是独立 LLM Agent。
- 分支状态在父进程内执行；Worker 在 map 节点中途崩溃会安全重跑只读分支，不支持分支级独立恢复。
- 不承诺外部调用 exactly-once；当前依赖父 Run 幂等键、租约与最终写入 fencing。
- `conflict_count` 只有 Scout 产生结构化支持/反证主张后才有完整含义，Phase 1 主要验证证据覆盖与安全。
- 冻结 A/B 数据所需论文尚未全部导入；完成人工复核和真实配对评测前不进入 Phase 2，也不宣称质量提升。
