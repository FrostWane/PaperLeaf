# PaperLeaf 生产 RAG 检索升级与验证报告

日期：2026-08-13

## 结论

本轮完成了生产同源评测、逐论文取证、弱结果查询改写、上下文化 Embedding、可选句窗重排和管理员观测。16 篇本地论文已经全部按新向量契约重新索引，旧向量不会与新向量混用。

当前结果支持两个结论：

1. 逐论文取证解决了“Top-5 被单篇论文占满”的范围覆盖问题。在当前可执行的 2 个冻结跨论文问题中，必需论文覆盖从 `3/4` 提升到 `4/4`。
2. 它尚未解决正确证据页排序问题。同一烟测的页级 Recall@5 仍为 `1/4`，完整证据组命中仍为 `0/2`，因此没有发布“Recall 已提升”或“达到 60%”的结论。

句窗 Cross-Encoder 保持默认关闭。既有 20 篇诊断中，该方案把 Recall@5 从 `68/90` 降到 `63/90`，并把 p95 增加到约 5 秒，不满足晋级门槛。

## 现象与根因

历史冻结报告表明，20 篇、90 个 test 问题的页级 RRF Recall@5 为 `68/90（75.6%）`。拆分后，单篇题已较强，跨论文题只有 `5/20（25.0%）`；Recall@40 已覆盖全部标注页，说明主要矛盾是跨论文覆盖和深层候选排序，而不是完全无法召回。

生产链此前还有一个评测缺口：离线基线使用确定性哈希向量，而真实服务使用 PostgreSQL FTS、Ollama Embedding、pgvector 与 RRF。两条链路不能互相替代，也不能把离线增量直接宣传为线上增量。

## 实现

### 生产同源评测

新增 `paperleaf_api.evaluation_production`，直接调用生产 `SQLLibrarySearch`，冻结：

```text
structure_aware_v2
→ PostgreSQL FTS / pg_trgm
→ 当前 Embedding 契约
→ pgvector
→ RRF
→ 页级去重
→ Top-5
```

运行前必须满足论文归属、arXiv 版本、Chunk 非空、切分策略和向量指纹全部一致。缺论文或索引过期时输出 `not_executed`，不会静默缩小论文范围。报告记录数据集、用例、检索代码、配置和索引指纹；回答与引用指标明确标记为 `not_measured`，避免把纯检索实验冒充回答质量实验。

### 逐论文取证

集合或全库中的 2～10 篇论文启用受控逐论文检索：

- 原问题按论文 scope 独立检索；
- Specialist 使用论文标题和比较维度构造确定性专属查询；
- 每篇保留独立候选，再按论文轮转合并；
- 最终证据仍执行用户、论文、Chunk 和物理页校验；
- 单篇和超过 10 篇的普通全库查询不产生逐论文放大。

### 弱结果查询改写

查询改写不再只在零结果时触发。触发条件包括：

- 无候选；
- 前五候选关键词覆盖低；
- 首位与次位分差过小；
- 中文问题检索英文论文；
- 比较、方法、实验、结果和局限等宽泛意图。

英文问题优先使用确定性补充查询，保留数字、缩写和技术实体；只有跨语言、低覆盖或零结果才调用模型，最多生成两条补充查询。逐论文向量查询批量发送给 Ollama，避免每篇论文单独建立模型请求。

第一轮真实烟测曾让 DeepSeek 参与所有比较问题的改写，单题耗时达到约 16～42 秒。改为“确定性优先、弱结果才调用模型”后，最终镜像中两组逐论文模式的本机中位数为约 4.0～4.8 秒；统一查询的首个冷请求为 11.9 秒。该数值来自同一台本机的 2 题烟测，只说明移除了不必要的模型等待，不作为稳定 SLA。

### 上下文化 Embedding

索引输入从纯 Chunk 正文改为：

```text
论文标题 + 可识别章节标题 + 物理页 + Chunk 正文
```

数据库仍保存原始 Chunk 正文，稳定 Chunk ID 和引用页码不变。向量指纹现在同时包含模型、维度、索引修订和输入格式：

```text
qwen3-embedding:0.6b / 1024 / revision 2 / paper_context_v2
```

配置或输入格式不一致时旧索引标记为不兼容，并降级关键词检索。2026-08-13 本地 PostgreSQL 中 16/16 篇论文均为 `ready`，且全部使用同一新指纹。

### 句窗重排

实现了 160～220 Token 的完整句窗：正常文本按句子边界切分；无标点的超长公式、表格或 OCR 行才在上限处确定性降级。每页取最高句窗分数并与 RRF 分数融合。

该能力由 `PAPERLEAF_RAG_RERANKER_ENABLED` 控制，默认 `false`。依赖缺失、模型加载失败或超时都会保留原 RRF 排序，并把降级原因写入 RAG Trace。

## 评测证据

### 离线诊断

本轮用当前 `structure_aware_v2` 重新解析 20 篇冻结 PDF，产生 2773 个 Chunk。历史报告使用 953 个 Chunk，两者语料切分快照不同，因此本表只能做本轮消融，不能覆盖或改写历史 `75.6%` 结果。

| 本轮诊断方案 | test Recall@5 | 完整证据组@5 | MRR@5 | 跨论文 Recall@5 | 跨论文完整组@5 | 跨论文 MRR@5 | p95 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 页级 RRF | 66/90（73.3%） | 63/80（78.8%） | 61.5% | 4/20（20.0%） | 1/10（10.0%） | 15.3% | 59 ms |
| 范围多样化 | 67/90（74.4%） | 64/80（80.0%） | 61.6% | 5/20（25.0%） | 2/10（20.0%） | 15.8% | 56 ms |
| 相同问题逐论文检索 | 67/90（74.4%） | 63/80（78.8%） | 62.1% | 5/20（25.0%） | 1/10（10.0%） | 20.3% | 60 ms |

逐论文检索相对本轮页级 RRF 将跨论文 MRR@5 提高约 5.0 个百分点，但 Recall@5 没有超过已有范围多样化，完整组还下降 1 题。因此它只作为生产范围覆盖保护，不作为离线 Recall 提升结论。

### 真实 PostgreSQL / pgvector / Ollama 烟测

环境：Docker Compose、真实 PostgreSQL/pgvector、`qwen3-embedding:0.6b`、revision 2。用例为冻结 test 中当前本地语料可完整执行的 `vit-vs-clip` 与 `resnet-vs-vit`，共 2 题、4 个期望证据页。

| 模式 | Recall@5 | 完整证据组@5 | MRR@5 | 必需论文覆盖 | 本机中位数 | 非法范围结果 |
|---|---:|---:|---:|---:|---:|---:|
| 统一查询 | 1/4（25.0%） | 0/2 | 10.0% | 3/4（75.0%） | 11941 ms | 0 |
| 相同问题逐论文检索 | 1/4（25.0%） | 0/2 | 10.0% | 4/4（100%） | 3981 ms | 0 |
| 逐论文专属查询 | 1/4（25.0%） | 0/2 | 12.5% | 4/4（100%） | 4825 ms | 0 |

样本只有 2 题，不能外推为稳定准确率或延迟。统一查询包含明显的冷请求，不能用它与两组后续暖请求直接计算稳定延迟增量；在扩大样本并轮换运行顺序前，性能门只能标记为未判定。

## 可观测性

每次 RAG Trace 现在记录低基数聚合字段：

- 召回通道：关键词、查询改写、向量、句窗重排；
- 处理器：逐论文取证、弱结果改写、句窗重排；
- 改写触发：零候选、低关键词覆盖、排名接近、跨语言、宽泛意图；
- 向量和重排降级原因；
- 当前 Embedding 输入格式与 ready/stale 数量。

这些字段可以在管理员 RAG/Harness 页面查看；不记录问题正文、论文 ID、Chunk ID 或用户 ID 到聚合指标。

## 测试与边界

已覆盖：多论文轮转、弱信号判断、中英文技术词、超长 OCR 行、重排降级、向量输入契约、并发检索诊断隔离、生产评测越权结果剔除、零召回分母、p95 nearest-rank 和管理员字段映射。

仍未完成：

- 完整 20 篇生产同源 test；本地共有 16 篇 revision 2 论文，但其中只有 6 篇属于该冻结集合，整套预检明确返回缺失 14 篇且 `not_executed`；
- 全新 50 篇、100 问隐藏集及配对 Bootstrap；
- 达到跨论文 Recall@5 60% 或 required-paper coverage@5 80% 的正式门禁；
- 一个通过 ≥3pp Recall、≥5pp MRR 且 p95 增量受控门槛的重排器。

后续应先补齐冻结语料并跑完整生产同源基线，再针对 Top-40 做训练域更匹配的重排实验。旧 test 已揭盲，只能诊断，最终数字必须来自新的隐藏集。
