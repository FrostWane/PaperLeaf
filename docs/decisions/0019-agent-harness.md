# ADR-0019：确定性 Harness 外壳与模型驱动工具内核

## 状态

已接受，2026-08-08。

## 决策

- PaperLeaf 将 Context、Memory、Skill、Tool 与 MCP 视为独立 Harness 子系统；
- LangGraph 继续负责身份、权限、步骤上限、人工确认、引用校验、恢复与持久化；
- 模型只在受控范围内选择一个主 Skill，并调用该 Skill 允许的强类型工具；
- 论文原文、工具结果和外部搜索内容一律视为不可信输入，不能修改系统权限或长期记忆；
- 会话摘要和长期记忆只辅助理解问题，论文事实必须重新从物理页 Chunk 召回；
- 每次运行保存内容私有的 Context Snapshot，并只向管理员暴露无正文的聚合指标；
- 五项能力均受 Feature Flag 控制，旧固定 RAG Graph 是功能不支持或故障时的回退路径。

## 原因

现有链路只保留最近少量消息，缺少当前页、选中文字、实体状态和长期偏好，无法稳定理解“原文怎么处理的”一类追问。完全固定的工作流又不能让模型按问题选择工具；完全自主的 Agent 则难以保证多用户权限和科研引用。混合式架构把概率性决策限制在确定性安全边界内。

## 信任边界

- 客户端阅读状态必须由服务端按用户与会话范围重新验证；
- 只有用户消息和用户设置可以产生长期记忆候选，PDF、模型回答和 Tool Result 无写入资格；
- MCP 首期仅允许管理员配置的只读学术搜索服务；
- 不保存隐藏思维链，不给模型数据库、文件系统、Shell 或任意 URL 访问能力；
- Prometheus 标签不得包含用户、论文、会话、问题、Chunk 或记忆内容。

## 未选择

- 把所有历史和全部 Skill 一次性塞入 Prompt：浪费上下文且降低相关性；
- 用会话摘要替代 RAG：压缩会损失可引用的物理页证据；
- 让普通用户连接任意 MCP：会扩大 SSRF、凭据和供应链风险；
- 为展示 MCP 重写已稳定的 arXiv、Crossref 和文献库检索。

## 后果

新增运行可以解释使用了什么上下文、Skill 和工具；旧会话按需生成摘要，既有论文无需重建索引。每个里程碑必须先在 Feature Flag 关闭状态验证兼容，再单独开启真实闭环。
