# PaperLeaf 安全说明

## 安全边界

PaperLeaf 处理私人 PDF、账号凭据和外部模型 Key。默认 Compose 适合本地验证；公网部署必须增加 HTTPS、网络隔离、强密钥、备份和运行监控。

## 身份与权限

- 关闭公开注册，由管理员创建用户并发放临时密码。
- 密码使用 Argon2id 哈希；服务端会话通过 HttpOnly、SameSite Cookie 保存。
- HTTPS 部署必须启用 Secure Cookie 与 CSRF 防护。
- 所有用户内容查询都应包含用户范围，不能依赖前端隐藏或检索后过滤。
- 管理员只管理账号、任务状态和错误元数据，默认不提供读取用户 PDF 与提问内容的入口。
- 禁止删除或降级最后一名管理员；停用用户时撤销其会话。

## PDF 与对象存储

- 上传时检查扩展名、PDF 文件头、大小、页数、加密标记和解析损坏状态；当前不把客户端声明的 MIME 当作可信依据。
- 文件名只作为显示信息，不直接拼接本地路径或对象键。
- MinIO Bucket 保持私有，通过鉴权 API 提供 Range 读取。
- API 与 Worker 容器使用非特权用户运行，并设置文件大小、页数和任务重试边界。
- PDF、OCR 文本与元数据均视为不可信输入，显示前转义。

## Agent 与模型

- 模型只获得完成请求所需的最小证据范围。
- PDF 中的指令不能覆盖系统规则或授权模型调用工具。
- Agent 工具使用结构化输入和服务端权限检查；网络与模型调用设置超时和受控重试。
- 不向 Agent 提供 Shell、任意 URL、数据库或文件系统工具。
- arXiv 导入固定允许域名、在重定向后复验域名、限制下载大小并校验 PDF 文件头，且要求用户确认。
- 服务端验证回答引用属于本次召回证据；证据不足时拒答。
- 检索结果非空不代表证据充分：页级检索门禁先验证匹配信号；配置模型后再用结构化答案支持检查区分“主题相关”和“事实可回答”。支持检查把 PDF 内容视为不可信数据，并且失败时关闭生成路径。
- 不记录隐藏推理、API Key 或无必要的完整 PDF 正文到运行日志。

## 密钥

- `.env` 已被 Git 忽略；仓库只提交不含真实凭据的 `.env.example`。
- 模型 Key、会话密钥、数据库密码和 MinIO 密码不得使用 `NEXT_PUBLIC_` 前缀。
- 生产环境优先使用部署平台的 Secret 管理功能，并定期轮换。
- GitHub Actions 对提交历史运行密钥扫描，但扫描不能替代人工检查。
- 若密钥被提交，应立即在提供方吊销并重新生成；从 Git 历史删除并不能撤销已泄露的密钥。

## 网络部署

- 只公开 HTTPS Web 入口；API 建议通过同域反向代理。
- PostgreSQL、MinIO API 与 MinIO Console 仅允许内部网络或受控运维网络访问。
- CORS 只列出实际来源；携带凭据时不允许通配符。
- 反向代理设置上传上限、请求超时、SSE 无缓冲和必要的速率限制。
- 定期更新基础镜像和依赖，在发布前审查依赖告警。

## 数据保留与外部服务

- 启用外部模型时，证据片段会发送给对应服务提供方；部署者应告知用户并核对其数据政策。
- 删除文献通过后台任务清理原件、页、Chunk、向量、集合/标签关系和关联作业。备份中的副本按部署者的保留周期过期。
- 日志应避免正文、Cookie、Authorization、API Key 和用户密码。
- 数据库与对象存储需要一致备份，并定期做隔离恢复演练。

## 已知边界

- 文献问答不能替代原文核查和专业判断。
- Prompt Injection 防护是分层控制，不存在仅凭提示词即可保证安全的方案。
- 自托管部署的主机、反向代理、模型服务和备份安全由部署者负责。
- 当前版本不面向多组织强隔离或受监管数据场景；此类使用需要额外审计与控制。

## 报告安全问题

不要在公开 Issue 中提交可利用细节、真实 PDF、账号、Token 或个人数据。优先使用仓库的 GitHub 私密安全报告功能；若该功能尚未启用，请先通过维护者公开资料建立私密联系。报告应包含受影响版本、最小复现、影响范围和建议缓解措施。
