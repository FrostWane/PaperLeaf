# PaperLeaf 安全说明

## 安全边界

PaperLeaf 处理私人 PDF、账号凭据和外部模型 Key。默认 Compose 适合本地验证；公网部署必须增加 HTTPS、网络隔离、强密钥、备份和运行监控。

## 身份与权限

- 关闭公开注册，由管理员创建用户并发放临时密码。
- 密码使用 Argon2id 哈希；服务端会话通过 HttpOnly、SameSite Cookie 保存。
- HTTPS 部署必须启用 Secure Cookie 与 CSRF 防护。
- 所有用户内容查询都应包含用户范围，不能依赖前端隐藏或检索后过滤。
- 管理员只管理账号、任务状态和错误元数据，默认不提供读取用户 PDF 与提问内容的入口。
- 禁止删除或降级最后一名管理员；停用用户时撤销其会话。

## PDF 与对象存储

- 上传时检查扩展名、PDF 文件头、大小、页数、加密标记和解析损坏状态；当前不把客户端声明的 MIME 当作可信依据。
- 文件名只作为显示信息，不直接拼接本地路径或对象键。
- MinIO Bucket 保持私有，通过鉴权 API 提供 Range 读取。
- API 与 Worker 容器使用非特权用户运行，并设置文件大小、页数和任务重试边界。
- PDF、OCR 文本与元数据均视为不可信输入，显示前转义。

## Agent 与模型

- 模型只获得完成请求所需的最小证据范围。
- PDF 中的指令不能覆盖系统规则或授权模型调用工具。
- Agent 工具使用结构化输入和服务端权限检查；模型调用统一设置超时、有限重试、主备切换和按用途隔离的熔断器。
- 不向 Agent 提供 Shell、任意 URL、数据库或文件系统工具。
- arXiv 导入固定允许域名、在重定向后复验域名、限制下载大小并校验 PDF 文件头，且要求用户确认。
- 服务端验证回答引用属于本次召回证据，并要求每条可见事实主张绑定合法引用；缺引用或伪造引用时丢弃原回答。
- 模型流先在 Worker 内缓冲为完整事实段落；只有引用归属与证据支持均通过时，段落才会同时进入助手消息和公开事件表。未经校验的草稿不会经 SSE 暴露。
- 会话论文范围由服务端根据当前用户和论文/集合关系解析并固化为 Run 快照；前端提交的集合或论文标识不能绕过资源所有权检查。
- SSE 只回放白名单事件和脱敏字段。递增事件序号用于断线补发，不包含提示词、模型草稿、隐藏状态或内部 Checkpoint 键。
- 问答 Markdown 禁止原始 HTML，只允许 `http`/`https` 外链；Chunk 引用由受控语法转换为页码按钮，普通链接不能伪造引用组件。
- 总结和结构图的模型 JSON 不是可信结果：服务端逐事实/逐节点验证引用属于当前论文证据，结构边必须引用已验证节点且不得形成循环。Mermaid 文本只由服务端从受控字段生成。
- 结构图失败时不把原始模型输出回显给用户或写入公开图形；缓存只保存验证后的 payload 或明确的降级摘录与原因。
- 检索结果非空不代表证据充分：页级检索门禁先验证匹配信号，回答生成后再逐条检查主张与证据。未配置检查模型时采用确定性原文覆盖门禁，配置后叠加结构化语义判定；检查不可用或不通过时关闭回答路径。
- 节点轨迹与模型尝试记录只保留节点名、用途、服务别名、模型名、状态、耗时和稳定错误码；不记录隐藏推理、提示词、响应正文、API Key、Base URL 或无必要的完整 PDF 正文。
- 用户取消先持久化并由 Worker 在执行边界传播到 Graph 和模型调用；租约令牌阻止过期 Worker 迟到写回。取消不作为服务故障累计，避免人为操作误触发熔断。
- 全文翻译只接受 `zh-CN`、`zh-TW`、`en`、`ja`、`ko` 五种目标语言。PDF 页文本始终放在不可信内容边界内，翻译模型没有工具、URL、Shell、数据库或文件系统访问能力。
- 译文落库前重新校验作业领取令牌、租约有效期、用户取消、论文删除和来源文本哈希。旧 Worker 不能刷新已经过期的租约；被取消的调用或已重新索引的页面也不能写回可见译文。
- 翻译日志和管理员任务页只记录用途、状态、进度与稳定错误码，不记录页面原文、提示词或模型回复。

## 密钥

- `.env` 已被 Git 忽略；仓库只提交不含真实凭据的 `.env.example`。
- 模型 Key、会话密钥、数据库密码和 MinIO 密码不得使用 `NEXT_PUBLIC_` 前缀。
- 生产环境优先使用部署平台的 Secret 管理功能，并定期轮换。
- GitHub Actions 对提交历史运行密钥扫描，但扫描不能替代人工检查。
- 若密钥被提交，应立即在提供方吊销并重新生成；从 Git 历史删除并不能撤销已泄露的密钥。

## Redis 与限流

- Redis 只承载可丢失的限流计数和幂等判定，不作为用户、任务、会话或 Agent 事件的数据源。
- 阅读上下文中的论文、集合、物理页和选中文字均由服务端复核；低置信度指代不会带着猜测进入检索或工具调用。
- 长期记忆默认由用户控制，管理员只能查看聚合容量，不能读取正文。论文事实、模型回答和工具输出禁止自动写入；停用或删除后不会再次装入上下文。
- Redis Key 不包含原始用户 ID、邮箱、提问内容或幂等键；相关标识在进入 Key 前使用 SHA-256 摘要。
- 相同幂等键复用首次限流判定，网络重试不会额外消耗额度；不同请求超过窗口限制时返回 `429` 和 `Retry-After`。
- Redis 连接失败时退回当前 API 进程内限流。该降级能保护单节点，但不能提供跨节点统一配额，因此必须记录并告警。
- Compose 不映射 Redis 宿主机端口；跨主机部署必须使用私网、认证和传输加密。

## 网络部署

- 只公开 HTTPS Web 入口；API 建议通过同域反向代理。
- PostgreSQL、MinIO API 与 MinIO Console 仅允许内部网络或受控运维网络访问。
- CORS 只列出实际来源；携带凭据时不允许通配符。
- 反向代理设置上传上限、请求超时、SSE 无缓冲和必要的速率限制。
- 定期更新基础镜像和依赖，在发布前审查依赖告警。

## 数据保留与外部服务

- 启用外部模型时，证据片段会发送给对应服务提供方；部署者应告知用户并核对其数据政策。
- 删除文献先持久化取消关联翻译，再通过后台任务清理原件、页、Chunk、向量、译文、集合关系和关联作业。备份中的副本按部署者的保留周期过期。
- 日志应避免正文、Cookie、Authorization、API Key 和用户密码。
- 数据库与对象存储需要一致备份，并定期做隔离恢复演练。

## 已知边界

- 文献问答不能替代原文核查和专业判断。
- Prompt Injection 防护是分层控制，不存在仅凭提示词即可保证安全的方案。
- 自托管部署的主机、反向代理、模型服务和备份安全由部署者负责。
- 当前版本不面向多组织强隔离或受监管数据场景；此类使用需要额外审计与控制。

## 报告安全问题

不要在公开 Issue 中提交可利用细节、真实 PDF、账号、Token 或个人数据。优先使用仓库的 GitHub 私密安全报告功能；若该功能尚未启用，请先通过维护者公开资料建立私密联系。报告应包含受影响版本、最小复现、影响范围和建议缓解措施。
