# PaperLeaf v3 P0 稳定性返工

本目录记录 `specialist_subgraph_v3` 的真实模型稳定性诊断。v3 Feature Flag 默认关闭，
这些结果不能解释为 v3 已优于 v1/v2。

## 结果

历史数据库审计发现 14 个分支超时、6 个 Schema 失败。返工按以下顺序进行：

| 阶段 | Run | 分支 | 成功 | 超时 | Schema 失败 | 安全降级 |
|---|---:|---:|---:|---:|---:|---:|
| 冻结 30 Run 批次 `a4ebe83` | 30 | 81 | 76 | 0 | 5 | 0 |
| 仅 Schema 重试 `bdd052b` | 4 | 9 | 7 | 0 | 2 | 0 |
| Schema 证据降级 `de3d92b` | 4 | 12 | 11 | 1 | 0 | 4 |
| 超时案例定向复跑 `0fda1a5` | 1 | 3 | 3 | 0 | 0 | Schema 1、超时 1 |

`de3d92b` 证明连续两次非法结构不再让整个分支失败：不可信模型主张被丢弃，只保留
服务端已验证的真实 Chunk。该批仍出现一个恰好 60 秒的模型超时，因此没有把上限继续
抬高，而是在 `0fda1a5` 加入同口径的超时安全降级。唯一超时案例定向复跑后，3/3 分支
进入成功终态；发生超时的分支记录 `timeout_fallback_used=true`。

## 安全边界

- 检索阶段没有取得合法证据时，超时仍是分支失败；
- 只有已经通过用户、论文 scope、物理页和 Chunk 校验的证据可以降级保留；
- 降级分支不产生模型主张、stance 或置信度；
- 最终答案继续经过引用合法性和语义支持门禁；
- Schema/超时安全降级次数进入 `harness_trace.branch_metrics`，不能伪装成正常模型成功。

## 证据与限制

原始回答含用户论文片段，因此保存在 `backend/evaluation/outputs/private/`，不进入公开仓库；
`run_manifest.json` 保存四份原始文件的 SHA-256。聚合分母由 PostgreSQL 中冻结 Git SHA 的
AgentRun 和 `branch_metrics` 计算。

30 Run 批次用于说明 60 秒配置下历史 14 个超时没有复现，但仍发现 5 个 Schema 失败；
后两轮是定向回归，只证明对应失败样本的修复行为，不能替代新的冻结全量 A/B 或人工盲评。
